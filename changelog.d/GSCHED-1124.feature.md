Every plan the Operation and Simulation servers generate is stored in the Sight database's new `generated_plans` table, with the time, type, description and site of the event that triggered it, the scheduler mode the server runs in (`mode`) and the server's `APP_VERSION`.
The plan is kept as JSONB in the shape the UI receives it, so changes to the plan format need no migration. A proposed plan is updated when it is accepted or discarded, with who decided and when, marked `superseded` when a newer plan replaces it first, or `expired` when the night ends or the next plan fails before anyone decides.
Storing never delays a plan: a database error is only logged. Set `PLAN_ARCHIVE_ENABLED=false` to turn it off. Run `alembic upgrade head` (done by the deploy workflows) to create the table.
